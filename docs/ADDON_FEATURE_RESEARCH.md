## สิ่งที่มีอยู่แล้ว

LIFF มีภาพรวมมูลค่าสุทธิ, CRUD ทรัพย์สิน/หนี้สิน 7 ประเภท, เพื่อนและกลุ่ม, การแชร์ และกล่องแจ้งเตือน (`apps/liff-web/src/features/app/AuthenticatedApp.tsx`). Backend มีการแจ้งเตือนประกันก่อนหมดอายุ 30/21/14/7/1 วันและส่งผ่าน LINE แล้ว (`services/asset-service/internal/usecase/insurance_usecase.go`) จึงไม่ควรเสนอการแจ้งเตือนประกันแบบเดิมเป็นฟีเจอร์ใหม่

## ข้อเสนอแรก: ศูนย์สิทธิ์แชร์

การแชร์เป็นจุดเด่นของแอป แต่ปัจจุบันผู้ใช้ต้องเข้าไปจัดการทีละเพื่อนหรือกลุ่ม การมีหน้า **“ใครเข้าถึงข้อมูลของฉัน”** จะช่วยให้ตรวจสิทธิ์ทั้งหมดจากจุดเดียวและถอนสิทธิ์ที่ไม่ต้องการได้ทันที

ขอบเขต v1:

1. แสดงรายการทรัพย์สินที่แชร์ พร้อมผู้รับ ประเภทผู้รับ และวันที่เริ่มแชร์; ค้นหาและกรองได้
2. ถอนสิทธิ์เฉพาะรายการ/ผู้รับที่เลือก พร้อมกล่องยืนยัน โดยไม่ลบทรัพย์สินต้นฉบับ
3. เพิ่ม backend API แบบแบ่งหน้าและตรวจว่าเจ้าของข้อมูลเป็นผู้เรียก ทั้งตอนอ่านและถอนสิทธิ์
4. ต่อ API ผ่าน gateway และ BFF allowlist; เพิ่มการทดสอบ owner/recipient/ผู้ไม่มีสิทธิ์ และการถอนสิทธิ์ซ้ำ

Backend มี `friend_items`, `group_items`, `email_items` ให้ต่อยอด และมี `GET /share/item/:type/:id/shared-targets` แล้ว แต่ผลลัพธ์ของเส้นนี้ยังไม่มี share-record ID ที่จำเป็นต่อการถอนสิทธิ์รายรายการจากหน้ารวม (`api-gateway/internal/domain/share.go`). สำหรับกลุ่ม ต้องตรวจสิทธิ์ตาม `group_item_viewers` จริง ไม่ถือว่าสมาชิกทุกคนเห็นข้อมูลเท่ากัน (`services/user-service/internal/repository/share_item_repository.go`).

เกณฑ์ผ่าน: เจ้าของเห็นการแชร์ทั้งหมดของตนเอง, ผู้ใช้คนอื่นเรียกดูไม่ได้, ถอนสิทธิ์แล้วผู้รับเปิดรายการนั้นไม่ได้อีก และรายการต้นฉบับยังอยู่

## ข้อควรทราบสำหรับฟีเจอร์ถัดไป

- LINE [`shareTargetPicker()`](https://developers.line.biz/en/reference/liff/#sharetargetpicker) เหมาะกับส่งลิงก์เชิญ แต่ผลลัพธ์ไม่เปิดเผยตัวตนผู้รับ จึงใช้แทนการกำหนดสิทธิ์แชร์ใน WealthVault ไม่ได้ ผู้รับต้องเปิดลิงก์และยืนยันตัวตนก่อน
- หากทำไฟล์รายงาน ต้องทดสอบวิธีเปิด/ส่งออกใน LIFF browser เพราะ LINE ระบุข้อจำกัดของ HTML `download` attribute ใน [เอกสารเปรียบเทียบเบราว์เซอร์](https://developers.line.biz/en/docs/liff/differences-between-liff-browser-and-external-browser/)
- หากทำ OCR กรมธรรม์ ต้องให้ผู้ใช้ตรวจทุกข้อมูลก่อนบันทึกและกำหนดนโยบายเก็บ/ลบเอกสารชัดเจน; [Google Document AI processor list](https://docs.cloud.google.com/document-ai/docs/processors-list) แสดงความสามารถด้านภาษาแตกต่างกันตาม processor จึงต้องทดสอบกับเอกสารภาษาไทยจริงก่อนเลือกบริการ

งานนี้เป็นการวิจัยและจัดลำดับเท่านั้น ยังไม่ได้แก้ฟีเจอร์หรือ API
